## Overview

acmcsuf.com is hosted on [Cloudflare Workers](https://workers.cloudflare.com/), a serverless execution environment that runs on Cloudflare's global edge network. It is cost-effective and performant for the project's needs.

The site uses the official [`@sveltejs/adapter-cloudflare`](https://github.com/sveltejs/kit/tree/main/packages/adapter-cloudflare) adapter to produce Worker-compatible output from the SvelteKit build.

## SvelteKit Adapter

The adapter is configured in `svelte.config.js`:

```javascript
import adapter from '@sveltejs/adapter-cloudflare';
import { vitePreprocess } from '@sveltejs/vite-plugin-svelte';

/** @type {import('@sveltejs/kit').Config} */
const config = {
  preprocess: vitePreprocess(),

  kit: {
    adapter: adapter(),
  },
};

export default config;
```

## Build Output

Running `vite build` compiles Svelte components, bundles JavaScript and CSS, and generates the following output structure:

```
.svelte-kit/cloudflare/
├── _worker.js          # Worker entry point
├── _app/               # JavaScript/CSS bundles
│   ├── immutable/
│   └── version.json
└── [other static files]
```

The `_worker.js` file is the entry point uploaded to Cloudflare Workers. Its size is enforced with a **50 KB limit** via `size-limit`:

```json
"size-limit": [
  {
    "path": ".svelte-kit/cloudflare/_worker.js",
    "limit": "50 KB"
  }
]
```

Run `npm run test:size` to verify the bundle stays within this limit.

## Wrangler Configuration

The full `wrangler.toml` at the project root:

```toml
# For more details on how to configure Wrangler, refer to:
# https://developers.cloudflare.com/workers/wrangler/configuration/

name = "acmcsuf-com"
main = ".svelte-kit/cloudflare/_worker.js"
compatibility_date = "2026-01-04"
compatibility_flags = [ "nodejs_als", "nodejs_compat" ]

[assets]
binding = "ASSETS"
directory = ".svelte-kit/cloudflare"

[observability]
[observability.logs]
enabled = true
head_sampling_rate = 1
invocation_logs = true
persist = true

# This uses vars defined in .env.production (make sure debug is off!)
[env.production]
routes = [
  { pattern = "acmcsuf.com", custom_domain = true }
]
workers_dev = true
preview_urls = true
```

### Key configuration fields

| Field | Value | Purpose |
|---|---|---|
| `name` | `acmcsuf-com` | Worker name in Cloudflare dashboard |
| `main` | `.svelte-kit/cloudflare/_worker.js` | Worker entry point generated by SvelteKit |
| `compatibility_date` | `2026-01-04` | Cloudflare runtime version pin |
| `compatibility_flags` | `nodejs_als`, `nodejs_compat` | Node.js AsyncLocalStorage and API compatibility |
| `assets.binding` | `ASSETS` | Name used to access static assets in worker code |
| `assets.directory` | `.svelte-kit/cloudflare` | Path to static files |
| `env.production.routes` | `acmcsuf.com` | Custom domain route for production |
| `workers_dev` | `true` | Enables `*.workers.dev` preview URLs |
| `preview_urls` | `true` | Enables versioned preview deployments |

## Automatic Deployment

The site uses Cloudflare's GitHub integration for automatic deployments:

- **Push to `main`**: Cloudflare builds the site, runs checks, and if all pass, deploys a preview. Once checks pass, the preview is promoted to production at `acmcsuf.com`.
- **Pull requests**: A preview deployment is created and a comment with the preview URL is added to the PR, updating on each new commit.

## Manual Deployment

<Warning>
  Manual deployment requires a `.env.production` file with the correct production variables and sufficient permissions in the Cloudflare account.
</Warning>

### Production deployment

```bash
npm run deploy
```

This runs `vite build --mode production` followed by `wrangler deploy -e production`, targeting the `[env.production]` configuration in `wrangler.toml`.

### Preview deployment

```bash
npm run preview:live
```

This runs `vite build --mode production` followed by `wrangler versions upload -e production`, creating a versioned preview. The generated preview URL takes the form:

```
<VERSION_PREFIX_OR_ALIAS>-<WORKER_NAME>.<SUBDOMAIN>.workers.dev
```

To create a named alias useful for tracking an in-progress feature:

```bash
vite build --mode production
wrangler versions upload -e production --preview-alias feature-name
```

To list all available versions (also visible in the Cloudflare dashboard):

```bash
wrangler versions list -e production
```

<Tip>
  Cloudflare allows rolling back to any listed version at any point from the dashboard or via the Wrangler CLI.
</Tip>

## Local Preview

To preview the site locally using Wrangler's dev server:

```bash
npm run preview
```

This builds the project with `vite build` and then starts `wrangler dev`.

## Additional Environments

Additional environments (e.g., staging) can be created by adding a block to `wrangler.toml`:

```toml
[env.staging]
route = "staging.acmcsuf.com/*"
workers_dev = false
```

Then create a `.env.staging` file and deploy with:

```bash
vite build --mode staging
wrangler deploy -e staging
```
