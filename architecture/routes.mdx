acmcsuf.com uses SvelteKit's file-system router. Every file prefixed with `+` under `src/routes/` corresponds to an endpoint or layout. All public pages live inside the `(site)` route group at `src/routes/(site)/`.

<Tip>
  For a full explanation of SvelteKit routing conventions, see the [SvelteKit routing docs](https://kit.svelte.dev/docs/routing).
</Tip>

## Route group: `(site)`

The `(site)` folder is a [route group](https://kit.svelte.dev/docs/routing#advanced-routing-route-groups). The parentheses mean it is **not** part of the URL — it exists purely to scope the shared layout (`+layout.svelte`) to all site pages without adding a path segment.

The shared layout at `src/routes/(site)/+layout.svelte` renders on every page and mounts the navigation bar, footer, and toast notification system:

```svelte src/routes/(site)/+layout.svelte
<Navbar />
<main><slot /></main>
<Footer />
<AcmToaster />
```

It also initialises the light/dark theme on mount and pre-loads the `/events` page data to improve perceived performance.

## Special files

| File | Purpose |
| --- | --- |
| `+page.svelte` | The page component. Receives data returned by `+page.ts`. |
| `+page.ts` | Universal load function — runs on the server during SSR and in the browser on navigation. Fetches data and returns it as props. |
| `+layout.svelte` | Wraps all pages in the same directory (and subdirectories) with shared UI. |
| `+error.svelte` | Rendered when any page throws an error. Replaces the failing page to show the user a friendly message. |
| `+server.ts` | An API endpoint (no UI). Returns a `Response` directly. |

## Dynamic routes

### `[x+40][username]` — contributor certificates

Path: `src/routes/(site)/[x+40][username]/`

The segment `[x+40]` is a SvelteKit [character encoding escape](https://kit.svelte.dev/docs/routing#advanced-routing-encoding) for the `@` symbol (Unicode code point U+0040). The full segment matches URLs of the form `/@username`.

| Sub-route | URL | Purpose |
| --- | --- | --- |
| `+page.svelte` | `/@:username` | Contributor certificate landing page. |
| `[repo_name]/` | `/@:username/:repo_name` | Repository-specific certificate. |
| `[repo_name].json/` | `/@:username/:repo_name.json` | JSON data endpoint for certificate data. |

### `[...id=link].svg` — QR code generation

Path: `src/routes/(site)/[...id=link].svg/+server.ts`

The rest parameter `[...id]` captures any path, the `=link` part applies a [parameter matcher](https://kit.svelte.dev/docs/routing#advanced-routing-matching), and the `.svg` suffix routes requests to this server endpoint. It generates QR code SVGs for short links.

The URL shortener hook in `src/hooks.server.ts` explicitly passes `.svg`-suffixed URLs through to this endpoint rather than attempting to redirect them:

```typescript src/lib/server/links/shortener.ts
// Pass to QR code generation endpoint.
if (url.pathname.toLowerCase().endsWith('.svg')) {
  return resolve(event);
}
```

## Server hooks

`src/hooks.server.ts` runs before any route handler and sequences two behaviours:

```typescript src/hooks.server.ts
export const handle = sequence(shortener(), handleTheme);
```

1. **`shortener()`** — resolves short links from `$lib/public/links` and issues a 302 redirect to the destination URL.
2. **`handleTheme`** — reads the `theme` cookie and rewrites `data-theme=""` in the page HTML to apply the user's saved light/dark preference.

<Note>
  Load functions in `+page.ts` files are *universal* — they run on the server for the initial request and in the browser for client-side navigations. To run code exclusively on the server, use `+page.server.ts` or place logic in `src/lib/server/`.
</Note>
