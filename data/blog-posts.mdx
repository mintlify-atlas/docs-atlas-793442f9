The [acmcsuf.com/blog](https://acmcsuf.com/blog) page is powered by GitHub Discussions. Posts are stored in the **Newsletter** category of the repository's Discussions tab and fetched at runtime via the GitHub GraphQL API.

## How posts are stored

Each blog post is a GitHub Discussion in the [`Newsletter` category](https://github.com/acmcsufoss/acmcsuf.com/discussions/categories/newsletter) of the `acmcsufoss/acmcsuf.com` repository.

- The discussion **title** becomes the post title.
- The discussion **body** (rendered as HTML) becomes the post content.
- GitHub **labels** applied to the discussion become the post's filterable tags.
- The discussion **author** is mapped to an officer record (if their GitHub username matches an `Officer.fullName` in `officers.json`).

## Creating a new post

<Steps>
  <Step title="Open the new discussion form">
    Navigate to [acmcsuf.com/blog/new](https://acmcsuf.com/blog/new). This shortlink resolves to the GitHub Discussions "new discussion" form pre-set to the Newsletter category.
  </Step>
  <Step title="Write your post">
    Fill in the title and body. The body supports GitHub Flavored Markdown.
  </Step>
  <Step title="Apply labels (optional)">
    Add labels to the discussion to categorize the post. These labels appear as filter chips on the blog page.
  </Step>
  <Step title="Submit the discussion">
    Click **Start discussion**. The post will appear on the blog page once the server fetches the latest discussions (cached for the session).
  </Step>
</Steps>

## Editing an existing post

To edit a published post, find the corresponding GitHub Discussion in the [Newsletter category](https://github.com/acmcsufoss/acmcsuf.com/discussions/categories/newsletter) and edit it directly on GitHub. Changes are reflected on the site on the next fetch.

## GitHub Discussions API integration

The server fetches posts using the GitHub GraphQL API. The query is defined in `src/lib/server/blog/gql.ts`:

```typescript
fetch('https://api.github.com/graphql', {
  method: 'POST',
  headers: {
    Authorization: `token ${GH_ACCESS_TOKEN}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ query: gql(GH_DISCUSSION_CATEGORY_ID) }),
});
```

The query fetches up to 100 discussions from the specified category, including:

| Field | Used for |
|---|---|
| `title` | Post title |
| `number` | Post ID (used in the URL `/blog/:id`) |
| `bodyHTML` | Rendered post content |
| `bodyText` | Plain-text excerpt |
| `createdAt` | Publication date (used for sorting) |
| `lastEditedAt` | Last-edited timestamp |
| `author.login` | Matched against `Officer.fullName` |
| `author.avatarUrl` | Fallback author avatar |
| `labels.nodes.name` | Post tags |

## Environment variables

Two environment variables are required for the blog to fetch live data:

```sh
# Your personal GitHub access token (prevents API rate limiting)
GH_ACCESS_TOKEN=YOUR_PAT

# The category ID for the Newsletter discussions category
GH_DISCUSSION_CATEGORY_ID=DIC_kwDOE7ysSc4CAC0o
```

Copy these from `.env.example` into your `.env` file. The `GH_DISCUSSION_CATEGORY_ID` value above is the public category ID for the Newsletter category and can be copied as-is.

<Warning>
Never commit your `GH_ACCESS_TOKEN` to the repository. The `.env` file is listed in `.gitignore` for this reason.
</Warning>

<Info>
If either variable is missing, `fetchBlogPosts` returns an empty result (`{ posts: [], labels: [] }`). Set `DEBUG_MODE_ENABLED=1` in your `.env` to use the bundled sample posts in `src/lib/server/blog/data.json` instead of calling the API.
</Info>

## RSS feed

An RSS feed of all blog posts is available at:

```
https://acmcsuf.com/feed.xml
```

The feed is generated by `src/routes/(site)/feed.xml/+server.ts`. It is served with `Cache-Control: max-age=0, s-maxage=3600`, so it is re-generated on each edge request but cached at the CDN for up to one hour.

Feed metadata:

- **Title**: acmCSUF README
- **Site URL**: https://acmcsuf.com
- **Categories**: derived from all published post labels
- **Item description**: truncated to the nearest word boundary at 250 characters of the post HTML
